# Candy Snake · 糖果贪吃蛇

糖果像素风贪吃蛇，包含“三关糖果闯关”和经典模式。核心、关卡、界面与平台适配分开，便于继续开发地图和规则。当前版本 1.2.0。

## 开始游玩

双击 `dist/index.html`，或运行 `npm run preview` 后打开终端显示的本地地址。单文件发布版本包含脚本、样式、字体与字体许可，可离线运行。

首页选择“糖果闯关”或“经典模式”。方向键 / WASD / 触屏滑动控制方向，小屏也提供方向按钮。空格 / Enter 开始、继续或重试；P / Esc 或暂停按钮暂停、继续。切到其他标签页自动暂停。

在闯关模式中，Q 键或“断尾”按钮立即移除尾部 3 节，至少保留 3 节，因此长度达到 6 才能使用。没有冷却或次数限制，长按 Q 只触发一次。暂停和结算时禁用。

## 糖果闯关

三关均每步 150ms、无时间限制。收集顺序自由，完成订单后走进绿色出口，才算通关。灰色出口可经过，也不会生成水果。

| 关卡          | 地图                  | 订单                           | 练习重点       |
| ------------- | --------------------- | ------------------------------ | -------------- |
| 01 糖果草地   | 16×16，开放地图       | 草莓×2、橙子×1                 | 学习订单与出口 |
| 02 巧克力庭院 | 16×16，两道带缺口的墙 | 葡萄×2、草莓×2、橙子×2         | 绕墙与路线规划 |
| 03 糖果小巷   | 12×12，错位窄通道     | 葡萄×2、草莓×3、橙子×2、西瓜×1 | 订单选择与断尾 |

- 同时最多 3 颗水果。非目标水果照常加分、增加蛇身，但不推进订单。
- 还缺的水果有固定四角标记和浅金底衬；同类收齐后取消标记。订单栏直接显示剩余数量，如“还缺 🍓×1”，收齐项自动移除，棋盘位置保持固定。
- 收齐提示、加分和连击文字显示在棋盘外。单类收齐提示约 0.9 秒，暂停冻结、重开清除；音效优先提示出口和收齐结果，避免同一步多套声音叠加。经典模式保留原有特效。
- 补货保证至少一颗属于未完成目标，必要时替换非目标水果；空间不足时减少数量，断尾后补齐。
- 订单完成后清空水果、点亮出口。断尾保留蛇头、方向、待执行转向、分数、连击和订单。
- 首次仅解锁第一关，通关依次解锁，可重玩已解锁关卡。失败重试当前关，重置蛇身、分数和订单。
- 保存已完成关卡，刷新恢复解锁。第三关完成后显示三关完成结算。只保存完成进度，不保存正在进行的局面。
- 闯关得分在本关独立显示，不写入经典最高分。

## 经典与共用计分

经典模式保留 20×20 棋盘、初始 3 节蛇身、150ms 步长，单颗水果，填满所有可用格后通关。撞墙、身体或障碍结束；未进食时可进入本步将移走的尾格。

两种模式均使用葡萄 / 草莓 / 橙子 / 西瓜，基础分为 1 / 2 / 3 / 5，随机权重为 50 / 30 / 15 / 5。第 2 个果实起为 1.5 倍，第 5 个起为 2 倍，单次得分向下取整；每 10 连击有彩虹特效。连击不设时间衰减。每步最多消费一次转向，队列最多缓存两条，忽略反向与重复输入。

## 开发与检查

需要 Node.js `^24.15.0 || >=26.0.0`，使用 npm 锁文件安装。没有游戏框架或运行时 JavaScript 依赖。

```bash
npm ci
npm run dev
```

| 命令                   | 用途                             |
| ---------------------- | -------------------------------- |
| `npm run dev`          | Vite 开发服务与热更新            |
| `npm run typecheck`    | TypeScript 严格类型检查          |
| `npm run lint`         | ESLint 零警告检查                |
| `npm run format`       | Prettier 格式化                  |
| `npm run format:check` | 只检查格式                       |
| `npm test`             | 全部规则、生命周期与界面回归测试 |
| `npm run test:watch`   | 监听测试                         |
| `npm run check`        | 类型、静态、格式检查与测试       |
| `npm run build`        | 构建单文件 HTML，并检查内嵌资源  |
| `npm run verify:build` | 检查资源内嵌和测试夹具隔离       |
| `npm run preview`      | 预览发布产物                     |

分享时只需要 `dist/index.html`。在 `src` 修改功能后重新构建；不要直接修改 `dist`。Git 忽略依赖、构建、缓存和压缩包；交付压缩包包含源码、文档和可玩产物。

## 修改入口

| 目的                         | 入口                                                    |
| ---------------------------- | ------------------------------------------------------- |
| 增加地图、订单与出口         | `src/content/catalog.ts` 的 `CAMPAIGN_LEVELS`、`LEVELS` |
| 增加模式、替换移动/计分/速度 | 同文件中的 `MODES` 和 `ModeDefinition`                  |
| 修改规则和胜利判定           | `src/core/engine.ts`                                    |
| 修改解锁与模式切换           | `src/app/campaign-progress.ts`、`game-coordinator.ts`   |
| 修改棋盘、水果、特效         | `src/render`                                            |
| 修改菜单、HUD 和文案         | `src/ui`、`index.html`、`src/styles.css`                |
| 接入手柄、桌面存档或音效     | `src/app/ports.ts` 与 `src/platform`                    |

完整接口、地图和模式示例见 [ARCHITECTURE.md](ARCHITECTURE.md)。批准的开发方案见 [PLAN.md](PLAN.md)。验收结果与工具验证边界见 [VALIDATION.md](VALIDATION.md)。

开发服务下可打开 `/tests/browser/index.html`，用固定种子 42、手动时钟重放正式模块，检查三关、Q 键、按钮、暂停、出口与刷新恢复。“收集一颗水果”按钮便于逐次观察剩余数量、收齐反馈和布局稳定性。验收页使用独立的 `candySnakeQa:` 存档前缀，不影响正式游戏；它不被打进发布 HTML。

## 存档与后续桌面版本

浏览器适配器使用 `candySnakeHighScore`、`candySnakeSoundEnabled` 和独立的 `candySnakeCampaignProgress`。进度采用版本化的连续已完成关卡列表，损坏记录恢复为仅解锁第一关。存储被禁用时仍可游玩，当前会话保留解锁结果，刷新后不保证保存。

不同网站、端口和文件页面的存档相互隔离。本轮不进行跨来源迁移。后续可用 Electron 桌面外壳复用核心和 Canvas，替换 `StorageAdapter`、接入手柄动作和成就事件。桌面打包与 Steam 发布属于后续版本。
